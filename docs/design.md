# SpeakerArrayの設計

## 構成

Kotlin・Jetpack Compose・ViewModelで画面と状態を管理します。Androidに依存しないDSP、WAV形式処理、設定JSONは`core`モジュールに分離しています。音声出力は1個のAudioTrackによる48 kHz・ステレオfloat32ストリームです。係数とFFT演算にはDoubleを使用します。画面の48 kHzはアプリ内処理レートであり、DACクロックの測定値ではありません。

`AudioEngine`はフォーカス、実ルート、音声スレッド、部分書き込み、開始・停止を管理します。`SourceEngine`は発振・共通ノイズ・スイープを生成し、`WavSource`は変換済みファイルを先読みします。`DspEngine`は畳み込みと経路切替、`FirDesigner`は係数設計、`ResponseAnalyzer`は応答と理論パターン、`SessionRepository`は形式検証を担当します。

音声再生中のスレッドで係数を設計したりファイルを読んだりしません。準備したFFTスペクトルをAtomicReferenceで渡し、ブロック境界で受け取ります。作業配列は事前確保し、メーターのUI通知は100 ms間隔です。

## 信号経路と切替

共通モノラル音源を左右へ分岐し、各chのFIR、追加遅延、ゲイン・極性・ミュート、共通出力ゲインを適用します。最後に物理左右と音声L/Rを対応付けます。ノイズは左右別々に生成しません。正弦波は共通の位相アキュムレータからsinとcosを作り、処理世代ごとの位相指定で合成します。発振器の位置を方式切替で初期化しません。

FIRと遅延を合成したカーネルを2048点FFTで処理します。ブロック長は256、履歴は1792サンプルです。最大の1025タップFIR、480サンプル遅延、33タップ補間を合成しても1537タップに収まります。新旧フィルタは同じ入力履歴を使い、空の履歴から切替先を動かすことはありません。

新旧出力を1440サンプル、30 msでクロスフェードします。途中の要求は最新のものを保持し、現在の切替後に適用します。設計には世代番号を付け、古い結果を適用しません。画面では編集目標、反映要求、適用済み世代を分けます。青いFIR曲線と理論グラフは再生中の適用済み設定を使い、切替中は直前の定常設定を表示します。

ゲイン・極性・ミュート・遅延もカーネル切替で平滑化します。正弦波の相対位相も新旧世代の出力クロスフェードに含めます。共通出力ゲインと正弦波の周波数は時定数240サンプルの一次平滑化です。開始・停止には480サンプル、10 msのフェードを付けます。停止フェード後はゼロを送り、AudioTrackをpause・flush・releaseして残留音を止めます。

## 位相と遅延

`Δt = 右の追加遅延 − 左の追加遅延`です。左に`max(0, −Δt)`、右に`max(0, Δt)`を割り当てます。入力範囲は±10000 µsで、負の物理遅延は実装しません。

サンプル未満の遅延は33タップのBlackman窓付きsincです。整数部を先頭のゼロ、端数をsincの中心位置で表し、補間器のDCゲインのみを1に調整します。整数遅延でも基準遅延16サンプルを含めます。ユーザーFIRをこの処理で正規化することはありません。

時間依存を`exp(jωt)`とし、追加遅延の理想位相は`−2πfτ`です。表示では実際の補間カーネルの複素応答を使います。発振器の右位相、FIR、補間、極性を合成して左右差を求めます。ミュートや深い零点では位相を定義しません。

## FIR設計

FIR長は左右共通の257・513・1025です。基準は中央タップ`D=(N−1)/2`で、フラットとバイパスは中央に1、その他に0を置きます。513タップの中央遅延は5.333 ms、1025タップでは10.667 msです。補間器やAudioTrackを含む総遅延ではありません。

EQは63、125、250、500、1000、2000、4000、8000、12000、16000 Hzの目標dB値を対数周波数上で線形補間します。ポイント外は端の値をDC・Nyquistまで保持します。16384点の偶対称振幅スペクトルを逆FFTし、ゼロ位相インパルスからN点を切り出して中央へ配置し、Blackman窓を掛けます。左右別々のピーク正規化は行いません。

LPFは理想sincにBlackman窓を掛けます。HPFは中央インパルスからLPFを引き、BPFは上下2つのLPFの差です。遮断周波数は理想振幅段差の境界で、窓掛け後の境界は概ね−6 dBです。固定幅の遷移帯域を保証するパラメータではありません。

任意係数は1〜N個を受け付け、不足分を末尾ゼロで埋めます。中央移動や振幅正規化はしません。NaN・Infinity・空配列・過長配列は拒否します。演算上の上限として絶対値1000000以下としています。有限係数でも出力が大きくなる場合は、メーターとクリップ表示で確認します。

位相は32768点の線形周波数格子でunwrapしてから対数表示点へ対応付けます。群遅延は複素応答の解析的な微分から求めます。振幅−80 dB未満では位相・群遅延を非表示にします。非対称係数に一律の中央タップ遅延を当てはめません。

## WAVと音源

ノイズの乱数列は再生ごとに同じシードで初期化します。白色ノイズは一様乱数をRMS 0.2に合わせ、ピンクノイズは7状態の固定IIR近似です。ノイズの帯域制限は257タップのBlackman窓BPFです。スイープの両端は10 msでフェードします。

WAVはRIFFチャンク長、奇数長パディング、fmt・dataを解析します。PCM16/24/32、IEEE float32、1・2ch、8〜192 kHzに対応します。WAVE_FORMAT_EXTENSIBLE、RF64、圧縮形式、複数dataチャンク、非有限のfloat値は拒否します。入力上限は1 GiBかつ2時間です。

異なるレートは96タップ、1024相のBlackman窓付きsincで変換します。カットオフは入力・出力の小さい側のNyquistの94%です。48 kHz入力は変換せず、PCM値を保持します。全ファイルをメモリ展開せず、入力キャッシュ8192フレームと固定の出力バッファで一時PCMファイルへ書きます。

再生時は32個の256フレームキューを使います。先読み不足時は当該ブロックをゼロにし、WAV不足回数を増やします。シークには世代番号を付け、古いキュー要素を破棄します。ループのクロスフェードは最大240サンプル、5 msで、短いファイルでは長さの半分までです。重複区間を消費するため、ループ周期はその区間分だけ短くなります。

Storage Access FrameworkのURIと永続読込権限を保存します。起動時にPCMキャッシュを再準備し、参照切れは停止状態で案内します。変換完了や読込失敗から自動再生しません。

## 理論プレビュー

左位置は`−d/2`、右位置は`+d/2`です。正面0°、物理右を正角として−90〜+90°を1°刻みで評価します。

```text
k = 2πf/c
P(f, θ) = HL(f) exp(−j k d sinθ / 2) + HR(f) exp(+j k d sinθ / 2)
表示dB = 20 log10(max(|P|/2, 10^(−60/20)))
```

HL・HRはゲイン、ミュート、極性、FIR、補間遅延の応答です。正弦波のみ発振器の相対位相を含め、共通出力ゲインは除きます。0 dB超過時は表示上限を広げます。右の追加遅延が正の場合、同相信号の整合方向は`Δt=d sinθ/c`を満たす正角側です。

## 設定形式とライフサイクル

JSONの必須識別子は`type`、`schemaVersion`、`sampleRateHz=48000`です。セッションは`speakerarray-session`のバージョン4で保存し、旧バージョン1・2・3も読み込みます。FIR単体は`speakerarray-fir`のバージョン1を維持します。未知のバージョンや異なるレートを拒否し、全体の検証後に既存設定を変更します。詳細な測定結果とA/Bを保存できるよう、セッションの上限は6400万文字としています。FIR単体は200万文字です。

セッションには音源、左右処理、FIR係数・設計値、向き、割当、間隔、音速、評価周波数、共通出力、A/Bを保存します。FIR単体はcoefficientsを使用し、任意のdesign情報で再設計しません。

CSVは1行1係数、空行可、任意ヘッダーは大小文字を区別しない`coefficient`です。多列CSVは拒否し、取込時に48000 Hzの指定を求めます。貼り付けは空白・改行・カンマ・セミコロン区切りと外側の角括弧を受け付けます。

フォーカス喪失、Activityのバックグラウンド移行、出力ルート変更では停止し、自動再開しません。Activityの構成変更ではViewModelを維持します。外部のファイル選択画面への移動も停止対象です。アプリ内ダイアログとタブ移動では停止しません。

## MIC測定によるフィルタ自動設計

「フィルタ自動設計」ページで出力とMICを別々に選びます。録音プリセットはMIC選択とは独立しています。デバイス一覧は接続通知で更新し、保存した種別・名前・取得可能なアドレスから端点を再同定します。同名候補が複数ある場合は開始しません。自動選択は開始前に内蔵端点へ解決し、実行中のIDを固定します。通常再生も同じ選択出力を要求します。

測定ではAudioRecordとステレオAudioTrackを1組だけ使用します。無音でストリームを開始し、双方の実ルートが要求と一致した状態を300 ms確認してから進みます。開始後もルート、録音の無音化、PCMの受信停止、出力不足、入力クリップ、システム音量を監視します。録音許可は別操作で取得します。

HFP入力ではAPI 31以降の通信デバイス指定、API 26〜30のSCO接続通知を使います。通信経路の確立と、メディア出力の指定は別の要求です。成立しない組合せでは無音のまま中止し、要求先と実ルートを表示します。終了時は通信モードと通信デバイスを元へ戻し、SCO・フォーカス要求を解放します。MIC音をスピーカーへ返す処理はありません。

正式反映後は、校正条件を保つため録音・通信経路・測定用AudioTrackを保持します。通常再生にも測定と同じAudioTrackを使い、出力先、USAGE_MEDIA／CONTENT_TYPE_MUSIC、通信モードを維持します。保持状態は常時表示し、明示的な解放、バックグラウンド移行、経路喪失で終了します。解放後とアプリ再起動後は保存済みの測定結果として表示し、同じ条件が続いているとは扱いません。

### PCMと時刻の契約

出力は48 kHz・ステレオfloat、入力は選択した8／16／32／44.1／48 kHz・モノラルPCM16です。HFPのアプリ側PCMレートから通信コーデックや音響帯域を推定しません。コーデックは不明として記録します。

測定信号は対数スイープを標準とし、位相既知マルチトーンも選択できます。各測定区間の前後に、同じ基準スピーカーから250 msのパイロット音を出します。パイロット、残響待ち、片側スイープ、録音余裕を1つのPCM配列にし、AudioTrackが受け付けたフレーム位置を記録します。解析や画面処理の間も専用スレッドが無音を書き込み、ストリームを作り直しません。

測定用の片側スイープは既存のFIR・極性・ゲイン・追加遅延・33タップ補間を通しません。現在の共通出力ゲインと左右割当だけを使用します。推定の参照信号は、その経路へ実際に書いた既知PCMに対応します。候補の効果確認には既存のDspEngineを使い、片側基準・未補正両側・補正後の全条件を同じ共通出力ゲインで2回ずつ測ります。既存DSPの共通16サンプル遅延は3条件に等しく含まれます。

パイロットとの相互相関から到着時刻を求め、同じ基準スピーカーの反復だけで共通オフセットと線形クロック比を推定します。左右を別々のピークで整列しません。クロック比の補正には32点の窓付きsinc補間を使い、解析時刻は48 kHz換算で統一します。50 msの共通前置余裕を取り、相対的な前進と遅延を保持します。残響保持時間は0.1〜2秒、通信遅延の探索余裕は0.2〜3秒で、それぞれ別設定です。

同期の方式バージョンは`common-template-16x-v2`です。最初の既知パイロットで粗い位置を求め、その録音波形を要求帯域に制限して共通テンプレートにします。全測定で同じテンプレートを使うため、録音経路による絶対時刻の偏りは左右共通です。相関の最大点付近を32点の窓付きsincで16倍補間します。各パイロットの送信位置、検出位置、予測位置、符号付き残差、相関係数、競合ピーク、相関曲率に対する雑音幅の参考値を保存します。雑音幅は統計的な信頼区間ではありません。

クロック差の上限300 ppmは維持し、旧0.35サンプルは警告に変更しました。最小6点・2秒以上の時間範囲、全点の相関係数0.65以上、中心相関ローブ外の競合ピーク比0.9以下を試験適用の条件とします。相関係数0.12未満は識別不能です。これらは波形の一致度と曖昧さの判定であり、左右の位相精度は別途反復測定で確認します。

大きな時刻変動の目安は要求帯域上端の1/4周期です。各側3点以上を持つ共通傾斜・段差モデルが、段差量の20%未満かつ直線モデルの最大残差の25%未満に誤差を減らす場合は、持続する時刻段差として中止します。曖昧なピークや未解決の大きな残差は診断を続けますが、試験適用しません。外れ値は除去せず、使用点と除外点を記録します。全体の時間モデルを左右別々のIRピークへ合わせる処理はありません。

残差は「パイロット時刻モデルの残差」としてsampleとµsで表示します。換算は48 kHz基準です。録音フレームのタイムスタンプ逆行、read/writeエラー、受信停止、出力underrun、クリップ、経路変更も監視します。タイムスタンプの対応有無と取得値を保存し、前後パイロットと複素応答の反復性を併用します。これらだけで、OS内部のすべての欠落やスイープ途中の不連続を検出できるとは扱いません。

測定全体は最大240秒です。解析済み区間のPCMを破棄して同じ録音バッファを再利用し、録音ストリームは継続します。開始前の見積もりがヒープ上限の65%を超える場合は拒否します。生のMIC録音を保存する機能は追加していません。

### 推定・設計・品質判定

ゼロ詰めFFTによる正則化したスペクトル除算で伝達特性を推定します。FFT長はスイープと残響保持区間を収める2の累乗で、左右に同じ時刻基準を適用します。設計グリッドは8192点FFT相当です。暗騒音の周波数別スペクトルからSNRを求め、左右各2回の振幅差・位相差も評価します。

基準側FIRは長さNの中央D=N/2に値1を置いた非ゼロの遅延です。補正側はN個の実係数を未知数として、次の周波数重み付き最小二乗を解きます。

```text
min_h Σk wk |Href(k) exp(-jωkD) + Hcorrection(k) FFT(h)(k)|²
      + λ ||h||² + 帯域外応答のペナルティ
N ∈ {257, 513, 1025}
```

正規方程式を共役勾配法で解きます。FFTを使う演算でも未知数は最初から有限長の因果実係数に限定し、理想比の単純な切り捨ては行いません。基準側の係数を保持し、補正側の周波数応答が最大ブーストを超える場合や、係数絶対値和による出力ピーク上界が0.9を超える場合は拒否します。音量は自動で上げ下げしません。

初期基準はSNR 20 dB以上、反復振幅差1 dB以内、位相差5°以内、有効ビン80%以上です。低域端・高域端では設計重みを滑らかに下げ、無効ビンと帯域外では補正側を抑えます。左右応答がほぼ同じ場合は警告を出し、設計を続けます。対称配置とモノラル化は1点のMIC応答だけでは区別できません。左右単独再生による割当確認は引き続き必要です。端点・割当・向きの変更で確認状態を無効にします。

品質不足でも全4097ビンのSNR、左右それぞれの反復振幅差・位相差、有効／無効理由を保持します。有効率が80%未満の場合は、20ビン以上連続する最長の有効帯域を提示します。「提案帯域に変更して再測定」で上下限を明示して変更でき、標準動作で要求帯域を縮めることはありません。

品質が成立した時点で評価マスクと重みを固定します。補正後の結果を見て評価対象を選び直しません。正式反映には、同じ検証信号のMIC録音エネルギーが片側基準・未補正両側の双方より3 dB以上低いことを2回確認します。1/3オクターブの部分帯域で3 dBを超える悪化がある場合も拒否します。基準音がノイズ床付近なら比較を中止し、補正後がノイズ床付近なら測定限界を明示します。数値はMIC録音上の相対低減量であり、校正されたdB SPLではありません。

前後の片側基準と未補正両側の反復性を、固定した全評価ビンで確認します。検証順は1回目が片側→両側→補正→片側、2回目が片側→補正→両側→片側です。同じ手順を帯域制限ノイズでも実施します。ノイズは固定シードのランダム位相スペクトルから作り、ピークを1以下に正規化します。長さは設定秒数を超えない最大の2の累乗フレーム数です。信号間の録音エネルギーは直接比較しません。

正式反映の判定には、同期信頼度、周波数別品質、固定マスクの維持、前後基準の安定性、別信号の効果、再生経路の維持をすべて要求します。3 dB改善だけでは合格しません。HFPでは「HFP録音上で確認した低減」と表示し、ヘッドセット内部処理の線形性や空間全体の消音を実証したとは扱いません。

通常再生の開始時には、検証済み係数と実際のPreparedProcessingを比較します。音量・モード・左右割当の一致と、係数絶対値和によるピーク上界0.9以下も必要です。再生中は入力PCMが有限値で振幅1以下であることを確認し、DSPクリップを検出したブロックは出力しません。任意音源での低減効果は未評価と表示します。

### 反映・保存・復元

試験適用中は元のSessionを変更しません。測定所有権、進行段階、候補、PreparedProcessing、正式保存を世代番号で結び、取消済み・古い世代を反映しません。成功時だけ実際に検証した任意係数を既存の係数モードへ設定します。相対位相・追加遅延・極性・左右ゲインは中立値に戻します。元の値はバックアップに残ります。

校正プロファイルには要求先・実ルート・PCM・プリセット・出力条件・帯域・品質・時刻推定・係数・元のセッションを保存します。FIR長の変更で使用できなくなったA/Bもバックアップから戻せます。失敗・取消時は元の処理・音量・A/Bを維持し、理由コードと取得済みの段階別診断を保存します。成功と失敗は共通の診断JSONスキーマ2を使い、判定方式・閾値、全解像度の配列、測定順、固定マスク、反復ごとの結果を含めます。未評価値はnullまたは項目の欠如で表し、0や合格で補いません。結果保存はStorage Access FrameworkでJSONへ書き出します。いずれの終了経路でも自動再生しません。

### 実装の分担

coreのAutoFir.ktは信号生成、同期、伝達特性推定、有限長FIR設計、品質判定を担当します。MeasurementDiagnostics.ktは構造化した判定、同期方針、通常再生条件を担当します。CalibrationRepository.ktとCalibrationTransaction.ktは保存互換性と正式反映を担当します。appのDeviceRoutes.kt、MeasurementAudio.kt、AutoFirMeasurement.kt、MeasurementResultStore.ktは、それぞれ端点・通信要求、録音再生、測定手順、結果JSONを担当します。AppViewModelとAutoFirUiは所有権、取消、表示、復元を管理します。


## 補正方式の独立保存と共通出力

「再生・調整」上部の「位相・振幅」「FIR」で方式を選びます。選択中の方式と音声へ適用済みの方式を区別し、準備中は切替中と表示します。FIR側は`Session.processing`に従来の係数・有効状態・ゲイン・極性・位相・遅延をそのまま保存します。単純補正側は`SimpleCorrection`に左右ゲイン・極性・ミュート、正弦波用の位相と遅延、広帯域用の遅延と基準周波数を保存します。方式切替で相手側の値を上書きしません。

単純補正では、保存した係数と同じ長さで中央に1を置いたフラットなFIRを使います。中央タップと補間器の基準遅延を保ちますが、任意の非対称FIRの群遅延まで同じとは扱いません。正弦波ではsin・cosの共通履歴から、各世代の位相・FIR・遅延・ゲインを組み合わせて出力を作り、全体を30 msでクロスフェードします。ノイズ・WAV・スイープでは共通モノラル履歴を使います。方式切替だけでは音源・WAV読込位置・AudioTrack・通信要求を作り直しません。

振幅比は右／左で、`20 log10(右/左)`のdB値と線形比を連動表示します。比の変更では左ゲインを保持して右ゲインを変更します。両chの範囲−60〜12 dBを超える場合は拒否し、共通出力を自動調整しません。0振幅はミュート・一時ソロで扱います。一時ソロは保存対象外で、FIR側と単純補正側のミュート設定を変更しません。

位相差は右−左、正値は右の進みです。相対遅延も右−左で、正値は右の遅れです。広帯域では遅延を保存し、基準周波数における実効位相を`−360 f_ref Δt + 極性差`で表示します。基準周波数だけの変更で遅延を変えません。位相入力から遅延へ変換するときも極性は保持し、表示を±180°へ折り返してから遅延を再構成することはありません。

正弦波から広帯域へ変更すると、単純補正側の遅延を`正弦波遅延 − 正弦波位相/(360 × 直前の発振周波数)`へ変換し、その旨を表示します。元の正弦波位相・遅延は別に保持します。±10000 µsを超える変換は、停止したうえで音源変更を拒否します。広帯域から正弦波へ戻すと元の正弦波設定を使用します。

AutoFIRの候補は一時領域だけで評価し、失敗・取消で方式や両設定を変更しません。成功時だけFIR側を更新してFIR方式を選びます。単純補正にはFIRの校正表示を引き継ぎません。測定値からFIRを手動変更した場合も未検証と表示し、「測定時のFIR設定を復元」で保存係数へ戻せます。保持中の測定経路は方式切替だけでは解放しません。出力、共通音量、配置、校正プロファイルの変更や機器接続の変更では保持を解除します。

A/Bは選択方式、両方式の設定、音源設定、校正プロファイルをまとめて保存します。共通音量・出力先は現在値を維持し、プロファイルが異なる場合は保持経路を解放して未検証に戻します。FIR長が異なるA/Bは停止後に呼び出します。旧A/Bは従来のFIR処理として呼び出します。旧セッションはまずFIR方式で従来の音を復元し、同じ手動値を単純補正側の初期値にも使います。

再生開始と処理切替前には、FIRと分数遅延を合成した係数絶対値和・chゲイン・共通出力からピーク上界0.9を確認します。範囲を超える値は無断で丸めず、共通出力を下げるよう案内します。通常再生も入力PCMの有限性と振幅1以下を検査し、DSPクリップを検出したブロックは出力しません。

## Bluetooth出力の組合せ制限

通常再生と自動設計は同じ`autoFir.output`を使用します。「再生・調整」と「フィルタ自動設計」の出力選択は同じ値を編集します。通常再生の開始にMIC選択や録音権限は必要ありません。

共通の`RoutePolicy`で、BTメディア出力と本体・アナログ有線・USB MICの組合せを許可します。SCO、LE Audioを含むBT入力と未知の入力種別はBT出力時に禁止します。HFP/SCO通話出力は2ch自動設計の対象外です。本体SP＋HFP MICは維持します。「自動」は内蔵端点へ解決してから判定します。

MIC選択肢は禁止理由付きで無効化し、既存の不適合設定を勝手に置き換えません。ViewModelの開始処理と音声ストリームの開始処理でも同じポリシーを検査します。無音開始後の実ルートにも適用し、要求IDとの不一致や途中の経路変更では停止します。再接続を含む機器通知で左右確認を無効にし、保持していた校正経路を解放します。自動再試行はありません。

BTメディア出力で本体・有線MICを使う場合は、SCO接続や通信モードを要求しません。HFPの300〜3,400 Hz設定は入力種別にだけ対応し、BT出力選択を理由に帯域を変更しません。共通遅延・クロック差には既存の時刻モデルを使い、探索余裕は0.2〜3秒の設定と全体240秒・メモリ上限で制限します。公開できないコーデック情報は不明と記録します。

外部機器の配置は端点の種別・名称・アドレスごとに保存します。本体の間隔や向きを自動コピーせず、外部配置が未設定なら理論パターンを未評価にします。理論プレビューで外部音源間隔と向きを設定すると、その配置と現在の補正方式を使用します。OSが単一のメディア出力として公開する機器を対象とし、BT機器2台への別々の同時配信は行いません。


## 単一周波数自動調整とFIR試験ポリシー

`adjustmentMethod`は自動調整方式、`correctionMode`は再生方式です。単一周波数の開始条件は広帯域FIRの品質判定から独立しています。対象周波数は`autoToneHz`に保存し、方式を単一周波数へ選び直した時点の正弦波周波数を初期値にします。

`ToneSearch`は、基準chを0 dB固定、補正chを−6〜+6 dBとして電力を探索します。`ToneMeter`が録音条件と取得範囲を渡し、探索側でも条件・変更順・非重複フレーム・待ち時間・有限電力・クリップを検証します。候補確定後の2回の独立した再測定に成功するまで、セッションへ反映しません。

Android側の`ToneMeasurement`は、同じ出力・録音ストリームと発振器を保ち、通常再生と同じ単純補正用DSPへ候補を送ります。立上り／消失の整定を確認した待ち時間と、候補ごとの窓安定性を使います。窓は0.5秒×3、評価開始待ち最大6秒、探索・検証最大64条件、全体最大600秒です。録音バッファは条件ごとに破棄できる既存構造を使い、全測定分のPCMを保持しません。

正式反映は`ToneTransaction`で単純補正側だけを更新します。`ToneProfile`は検証周波数、値、音量、端点設定、配置、結果、復元用設定を保持します。A/Bにも同じプロファイルを含めます。経路保持中のプロファイル実体と条件が一致した場合だけ検証済み表示を出し、再起動や設定取込だけでは認定を復活させません。失敗・取消は元のセッションを変更しません。

FIRの`QualityPolicy.STRICT`は20 dB・1 dB・5°・80%、`QualityPolicy.TRIAL`は20 dB・2 dB・20°・80%です。共通時刻の信頼度と既知の取得異常は別に検査します。試験用マスクを設計前に固定し、後段の複素反復チェックにも試験ポリシーを明示して渡します。録音電力は、基準の観測最小値と候補の観測最大値へノイズ推定を加味した保守的比較も通す構造です。部分帯域悪化制限は維持します。

集計方法、探索順、下限の計算式、保存済み8回への影響、実測との区別は[解析レポート](auto-adjustment-analysis.md)を参照してください。BT端点制限は単一周波数とFIRで共通の`RoutePolicy`を使用します。


## 保存FIRの再利用と現在の検証状態（2026-11-07）

保存FIRは、MIC・通信経路の解放後、アプリ再起動後、設定JSONの読込後も、そのまま通常再生に使用できます。「再生・調整」でFIRを選び、共通出力先と音量を確認して再生します。係数の編集や校正プロファイルの削除、再測定は不要です。通常再生では録音権限を要求せず、MIC録音やHFP通信を開始しません。出力には現在の共通出力設定を使い、保存時の機器へ戻したり、不明な出力から別機器へ切り替えたりしません。

再生開始と処理更新では`PlaybackSafety`で係数の有限性と範囲、ピーク上限0.9を検査します。実際の出力ルート、PCM異常、クリップ、フォーカス喪失の検査も続けます。`CalibrationPlaybackPolicy.matches`は現在の検証状態だけを判定し、その不一致だけで再生を拒否しません。

「現在の効果は未検証」には、測定経路の解除、別方式・別FIRに対応する経路、測定条件の変更を理由として表示します。手動編集したFIRでは測定時の係数を保持し、復元操作で戻せます。「過去のFIR測定結果」で保存結果を表示・書き出せます。「FIR効果を再確認（条件設定へ）」は条件画面へ移動する操作で、測定を開始しません。設定保存形式は4のままです。

現在の検証済み表示には、対応するFIRプロファイルを受理した際の経路を保持し、音量・係数・端点・測定条件が一致していることを求めます。表示は測定帯域と測定時の2信号に限定します。保存係数の一致だけでは復活せず、単一周波数方式の成功結果も以前のFIRの検証には使いません。

単一周波数探索後に以前のFIRへ切り替えても、保持中の経路を利用できます。同じ音源・共通音量・配置・端点での方式往復では、AudioTrackと録音スレッドを維持し、世代更新とクロスフェードで処理だけを切り替えます。経路喪失時は停止し、通常再生へ自動移行しません。通常再生を再開するにはユーザーが再生操作を行います。

## 実験用FIRと固定候補の比較（2026-11-07）

### 候補生成と正式判定

自動設計ページに「実験用FIR」を追加しました。通常再生の方式は「位相・振幅」「FIR」の2つです。実験用候補は`ExperimentalLibrary`で管理し、正式な`CalibrationProfile`へ登録しません。候補生成と比較は現在の両補正スロットを変更せず、明示的な手動適用だけがFIRスロットを更新します。保存FIRの通常再生、単一周波数探索、既存の正式合格条件は維持します。

`ExperimentalFir.readDiagnostic`は診断スキーマ2のレート・配列・測定順・応答順・共通時刻モデル・PCM異常を検査します。有効率や反復品質の不足は記録したまま生成できます。同期の信頼度不足は`PILOT_AMBIGUOUS`に限り、時刻モデルが計算可能で残差が対象上限周波数の1/4周期以内なら暫定応答を利用します。旧0.35 sample超過の警告も保持します。時刻段差、不明なクロック、欠損、識別不能パイロット、クリップ、非有限値、無信号、経路不一致は拒否します。同期フラグの書換えや左右別の強制整列は行いません。

生成処理は既存の`AutoFirDesigner`を呼びます。集約候補には`trial-power-v1`の設計重みを使い、正の重みが20ビン以上なら有効率80%未満でも設計へ進みます。交差候補は学習側のSNRだけから重みを決めます。基準chを非ゼロ・0 dB・共通遅延で固定し、補正chに別の相対位相・遅延・ゲインを重ねません。有限係数・収束・全周波数ブースト上界・DSPピーク上界0.9以下を検査します。生成失敗も理由付きの候補として保持し、再生可能にはしません。

候補には元診断SHA-256、候補ID、係数ハッシュ、設定、設計ビン、連続区間、不足理由、暫定時刻モデルを保存します。係数ハッシュはFIR長、実係数、位相、遅延、ゲイン、ミュート、極性、有効状態の固定バイナリ表現から計算します。実際の有限長FIRと分数遅延器を含む予測は、要求帯域全体と設計ビンを分けます。低SNR区間も全帯域に含め、評価不能値はnull、増音は負値のまま残します。

### 連続ストリームによる比較

`ExperimentalMeasurement`は1組の`MeasurementAudio`と同じ`SourceEngine`・`DspEngine`を維持します。比較処理には伝達特性推定や設計器の呼出しがありません。開始・各条件の前後・終了時に固定候補の係数ハッシュを検査します。端点には現在の共通設定を使い、本体SP＋HFP MICを許可し、BT出力＋BT MICは既存の`RoutePolicy`で拒否します。入力先を自動変更しません。

評価信号は48 kHz・8,192フレーム周期の帯域制限ノイズです。要求帯域のFFTビンごとに同じ振幅と擬似乱数位相を与え、シード`0x45585046`、ピーク0.8で生成します。周期ごとのフェードを加えず、条件変更でも音源位相を継続します。全条件で共通出力、OS音量、音源、左右割当、端点、評価時間をそろえます。片側基準は基準chだけ、無補正両側は左右等ゲイン・相対位相と遅延0・極性反転なしです。FIR長と中央タップ＋16フレームの共通基準遅延をそろえ、保存された単純補正を重ねません。

開始前に帯域、シード、0.512秒×3窓、3ラウンド、最低待ち時間、最大待ち8秒、全体上限240秒を固定します。最低待ちは`max(2秒, latencySeconds + tailSeconds + 0.1秒)`です。開始後に片側の立上りと消失を2回確認し、最後の安定窓の終端へ0.5秒を加えた時間と最低待ちの大きい方を実待ち時間にします。8秒を超える場合は測定不能として終了します。計画と観測した待ち時間は結果に保存します。

各条件ではDSPの適用世代とクロスフェード完了を確認してから、待ち時間後の新しい録音フレームを採用します。3窓の変動が0.75 dB以内、またはノイズ床付近であることも確認します。立上り確認では暗騒音の10倍を超える信号、消失確認では暗騒音の4倍以下を要求します。整定しない場合は上限付きで待ち、前条件の録音を採用しません。クリップ、PCM異常、経路・OS音量変更、フォーカス喪失、取消では停止して経路を解放します。

比較順序は次のとおりです。Sは片側基準、Bは無補正両側、Cは固定候補です。

| 区間 | 順序 |
|---|---|
| 開始 | 暗騒音 |
| ラウンド1 | S → B → C → B → S |
| ラウンド2 | B → S → C → S → B |
| ラウンド3 | S → B → C → S → B |
| 終了 | 暗騒音 |

各基準を候補の前後に置き、ラウンド別の値、条件順序、各窓の電力、取得範囲、出力フレーム、世代を保存します。録音PCMは既存の240秒分の上限を保ち、条件ごとに不要な範囲を破棄します。48 kHz・Float録音バッファは最大46,080,000 bytesで、全測定分の追加PCMを蓄積しません。

### 電力とノイズ床の扱い

録音は公称レートで48 kHzへ変換します。クロック誤差や位相を合わせる再推定は行いません。8,192点の矩形窓1周期を単位に、片側スペクトルの`|FFT|² / (N × 窓の二乗和)`を求めます。線形電力で平均し、要求帯域を積分してから`10 log10(基準 / 候補)`へ変換します。繰り返し波形にHann窓を掛けると窓位置で入力エネルギーが偏るため、整数周期の矩形窓を採用しました。表示はMIC録音上の相対電力で、校正SPLではありません。

前後暗騒音の最大窓電力をノイズ床とします。基準の最小窓がノイズ床の10倍以下なら評価不能です。候補がその範囲に入る場合は測定限界として、`10 log10((基準の最小窓 − ノイズ床) / (候補の最大窓 + ノイズ床))`による保守的下限を表示します。点推定と下限を保存し、候補ゼロから無限大の低減を作りません。片側比と両側比を併記します。

基準の最大・最小窓の差が2 dB以下、候補の差が1.5 dB以下またはノイズ床付近、暗騒音の差が3 dB以下のときに再現性ありと扱います。それ以外は「参考値・再現性不足」です。評価可能で安定し、両方の保守的下限が3 dB以上なら「実験比較で低減を観測」と表示します。この状態でも`formalAccepted=false`で、正式合格へ昇格しません。評価不能、再現性不足、効果不足は別表示です。

補助評価の設計対象ビンは比較開始前に固定します。測定後に有利な周波数を選びません。グラフには要求帯域の片側比・両側比、低SNR区間、設計対象外を示します。縦軸の表示範囲は±30 dBですが、JSONとCSVには範囲外の数値も残します。

### 保存、手動適用、画面

セッション保存形式は5となり、形式1〜4も読み込みます。実験用候補単体は`speakerarray-experimental-fir`の形式1、比較は`speakerarray-experimental-comparison`の形式1です。取込時に係数ハッシュと再生安全性を検査し、比較履歴が同じ候補ID・係数ハッシュであることを確認します。

候補は12個、比較は1候補3件、各比較JSONは400万文字、候補レポートと比較履歴の合計は2,400万文字を上限とします。比較開始前に400万文字分の空きを確保します。超過時はJSON保存と一覧整理を案内し、自動削除しません。生PCMを履歴へ保存しません。

手動適用では元セッションを復元用に保存し、FIRだけを更新します。位相・振幅スロット、校正結果、長さの異なる旧A/Bと両方式のA/Bを保持します。FIR長の異なるA/Bは停止後に呼び出します。比較終了・失敗・取消では元のセッションへ戻し、停止状態にします。履歴は係数・音量・ルート・設定とともに残り、再起動や読込後は過去の結果として表示します。現在の効果を検証済みとは表示しません。

横置きでは左にデータ選択、生成、候補選択、比較、保存、手動適用を置き、右に予測グラフと比較履歴を表示します。狭い画面は縦スクロールに切り替えます。停止と取消はスクロール外に置き、品質不足理由と窓別の値は詳細表示へまとめます。最新の診断を選べるため、新規測定が品質不足で終わった場合もPCでJSONを編集せず候補生成へ進めます。通常再生でMIC権限を要求することはありません。

3セッションの生成結果、予測値、再実行コマンド、操作手順は[実験用FIRレポート](experimental-fir-report.md)に記載しています。
