# 広帯域FIRの実機比較手順

主試験は300〜3,400 Hzです。500〜1,000 Hzや単一周波数探索での成功は前提にしません。以下はAndroid GUIで行う手順です。実装後の依頼により、USB接続のXQ-FS44へAPKを更新インストールし、その後の明示依頼でWi-Fi ADBから2候補・6比較を実施しました。結果と操作上の問題は[実機検証報告](wideband-live-validation.md)に記録しています。測定帯域は要求・評価範囲で、HFPの全域に十分なSNRと位相再現性があることを保証しません。

現在の版では、大きな診断JSONが読込上限に達する問題と、保存完了表示後もJSONが0バイトになる問題が見つかっています。保存後はファイルを開き、候補IDと比較履歴が読めることを確認してください。空ファイルの場合は履歴を整理せず、アプリ内のデータを保持します。今回の復元経緯は上記報告に記載しています。

## 準備

1. [検証記録](validation.md)の「広帯域実証の準備」にあるAPKのSHA-256を確認してください。versionName `0.1.0`、versionCode `1`は前回と同じなので、版番号だけでは区別できません。APKは`app/build/outputs/apk/debug/app-debug.apk`です。2026-11-07 19:25:24にUSB接続のXQ-FS44へ更新インストール済みです。別の端末を使う場合は、同じSHA-256のAPKをインストールしてください。
2. スマホを横置きで固定し、「再生・調整」の「左右の確認」で片側ずつ再生して左右割当を確認します。MICの位置と向きも固定し、スマホとMICの距離、机・壁との位置関係をメモや写真に残します。
3. 「フィルタ自動設計」で本体SP出力とHFP MIC入力、録音プリセットを確認します。「高度な設定」で入力PCMを確認し、要求／実ルートも記録します。停止中の実ルートは未確認なので、測定結果JSONに保存される実ルートと照合してください。BT出力＋BT MICは禁止のままで、入力が自動変更されることはありません。
4. 共通出力と端末音量の段数を記録します。初回は以前の共通出力−24 dBを参考にし、測定・比較中は固定してください。変更が必要なら一組の試験を終了し、別の試験名で変更後の条件を記録します。会話や物の移動を避け、測定中の身体位置もそろえます。

## 現在の設置で測定し、候補を作る

1. 「フィルタ自動設計」で「広帯域FIR」を選び、「主試験帯域 300〜3,400 Hz」を押します。この操作は帯域だけを変更します。起動時には保存設定を変更しません。
2. FIR長1,025 taps、正則化0.01、最大ブースト6 dBを初回の基本条件として確認します。元の実設定が異なる場合は変更前後を記録してください。「自動調整」で現在の配置の伝達特性を測り、終了後に「結果保存」で元診断JSONを保存します。
3. 正式自動設計が成功して設定へ反映した場合は、その事実も記録します。品質不足で終了しても、実験用の生成条件を満たす診断なら次へ進めます。時刻モデル不成立、PCM異常などの生成禁止理由は無視しません。
4. 「実験用FIR」へ進み、「最新の診断結果を選択」を押します。保存診断なら「保存診断／候補JSONを読込」を使います。元測定帯域と設計帯域が300〜3,400 Hzであることを確認し、「設計」で「2反復の集約」を選んで「実験用候補を作成」を押します。
5. 生成成否、候補ID、係数ハッシュ、品質不足理由、予測を記録し、「候補・結果を保存」でJSONを保存します。未測定範囲への帯域拡大は拒否されます。500〜1,000 Hzの診断の設定欄を広げるだけでは、広帯域の候補を作れません。

以前の設置を再現できない場合、古い候補の効果低下だけで測定方式の失敗とは結論しません。主試験には現在の設置で測定・設計した候補を使います。候補生成や比較の完了だけで現在のFIRを上書きすることはありません。

## 同じ候補で3回比較する

1. 選択中の候補IDと係数ハッシュ、画面の「設計」「比較評価」が300〜3,400 Hzであることを確認します。配置、共通出力、端末音量、左右割当、端点は固定してください。
2. 必要なら「比較用MIC権限を許可」を押し、「候補を比較測定」を実行します。1回の操作で、同じ連続ストリーム上の3ラウンドと前後の暗騒音を測ります。終了まで最大240秒です。停止・取消は画面のスクロール外にあります。
3. 終了後は全帯域の片側比・両側比・保守的下限、サブバンド表、周波数別グラフを確認し、「候補・結果を保存」で結果JSONを保存します。実行IDと日時、完了・評価不能・中止・取消の区別も記録します。
4. 候補を再設計せず、同じ条件で比較操作をさらに2回行います。合計3回の独立した実行を記録し、正常完了なら内部ラウンドは計9回です。同一実行内の3ラウンドは連続接続中の比較、別実行は音声経路を開き直した比較です。
5. 失敗・取消で履歴が3件になった場合は、下記の退避・整理を行って同じ候補で再試行します。条件を変えた場合は、同条件の反復へ混ぜず別の試験として記録します。

比較ボタンは候補を一時的に出力して測るため、初回の実証に「手動適用」や聴感判定は不要です。既存の位相・振幅補正を重ねず、片側基準・無補正両側・候補を独立した条件で比較します。終了時には元設定を保持して停止し、自動再生しません。聴感コメントを残す場合はMICと耳の位置の違いも書いてください。

## 比較履歴を退避して整理する

「比較履歴を退避」で保存先を選び、JSON保存の完了を確認します。その後、整理したい実行のチェックボックスだけを選び、「選択した退避済み履歴を整理」を押します。候補ID・係数・設計条件・元診断との対応、手動適用中のFIR、両補正スロット、A/B、過去の校正、元に戻す設定は保持します。

保存先の選択を取り消した場合や書込みが失敗した場合は、履歴を整理できません。保存成功だけでも自動削除しません。アプリのプロセス終了後は保存成功の確認状態を引き継がないため、整理前にもう一度退避してください。退避JSONには候補と比較履歴があり、後で読込・解析できます。旧履歴で日時が保存されていなければ「日時不明」と表示します。新しい実行には、履歴整理や再起動後も別の実行IDを割り当てます。

## 結果の読み方と次の分岐

全帯域と各サブバンドは、MIC録音上の相対電力です。校正SPLではありません。正値は低減、負値は増音です。サブバンドは300〜500、500〜1,000、1,000〜2,000、2,000〜3,400 Hzで、境界ビンは重複させません。ノイズ床付近では点推定の代わりに下限を表示し、基準がノイズ床付近なら評価不能とします。全帯域のSNRが十分でも、サブバンドは評価不能になることがあります。

| 観測結果 | 次に確認すること |
|---|---|
| 両基準比で安定した低減 | 同じ設置で新しく測定・設計し、別候補での再現性を確認 |
| 小さいが再現する低減 | 予測との差、サブバンドごとの効果 |
| 全帯域は改善し、一部で増音 | 増音帯域を残して報告し、必要なら別の帯域限定試験を計画 |
| 実行内・実行間の変動が大きい | 基準変動、暗騒音、経路・入力処理、設置の変化 |
| 安定して効果なし、または増音 | 左右割当、候補と元診断の対応、予測とのずれ |
| 整定不能、基準がノイズ床付近 | 測定成立性を確認し、キャンセル効果の結論は保留 |

3 dB以上は次の実験へ進む目安です。正式合格へは昇格せず、3 dB未満の値や増音も保存します。約932 Hzを除外したり、成績のよい帯域へ自動縮小したりしません。

## 記録と結果ファイル

[設置・測定記録テンプレート](wideband-record-template.md)と[比較集計CSVテンプレート](templates/wideband-comparison-template.csv)を試験ごとにコピーしてください。JSON退避前後の結果は、同じ候補ID・係数ハッシュと異なる実行IDで対応付けます。実行日時、音量・ルート変更を確認してから同条件の反復をまとめます。

```powershell
python tools/summarize_comparisons.py comparison-results.csv archive1.json archive2.json archive3.json
```

この集計は同じ実行IDの同一内容を重複計上せず、内容が異なればエラーにします。中止・取消や測定値の欠落を成功値や0で補いません。旧JSONに実行IDがなければファイルSHA-256と格納位置で識別し、新規実行とは区別します。実測JSONを取得した後、予測との差と同一候補の再現性を解析して次の試験を決めます。
