# SpeakerArray

横置きのスマートフォンで、2つのスピーカーによる干渉を試すAndroidアプリです。正弦波、ホワイトノイズ、ピンクノイズ、スイープ、WAVを再生し、左右のゲイン・極性・遅延・FIRを画面から調整できます。FIRの設計・係数編集と理論指向性の表示も端末内で行います。

リポジトリ: [hebowiz/SpeakerArray](https://github.com/hebowiz/SpeakerArray)

理論グラフは実測値ではありません。内蔵スピーカーの左右独立性、筐体、OSの音声加工、反射の影響は実機で確認してください。

## ビルドと起動

Android 8.0以上を対象とします。ビルドにはJDK 17、Android SDK Platform 34、Build Tools 34.0.0を使用します。Gradle 8.7、Android Gradle Plugin 8.5.1、Kotlin 1.9.24、Compose Compiler 1.5.14、Compose BOM 2024.06.00を固定しています。既存のSDK・JDKとの互換性を優先した構成で、NDKは不要です。targetSdkは34であり、Google Playの公開要件への対応は別途必要です。

Android Studioでリポジトリのルートを開き、Gradle JDKを17に設定してください。初回同期にはネットワーク接続が必要です。アプリ自体に通信権限はありません。SDKの場所は`local.properties`の`sdk.dir`で指定できます。

WindowsのPowerShellでは次を実行します。

```powershell
.\gradlew.bat :core:test :app:lintDebug :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

macOS・Linuxでは`./gradlew`を使用します。デバッグAPKは`app/build/outputs/apk/debug/app-debug.apk`に生成されます。リリース用の署名鍵は含めていません。

UIテストには短時間の音声再生と画面サイズ変更が含まれます。音声出力を無効にしたテスト用エミュレータで実行してください。

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest
```

GitHub ActionsはDSPテスト、Android Lint、デバッグAPKのビルドを実行し、APKとレポートを保存します。ワークフローは`.github/workflows/android.yml`にあります。

## 初回の操作

起動時は必ず停止状態です。最初に通常・逆向きの横置きを選択します。共通出力は初期値−24 dBです。端末本体の音量も確認してから再生してください。

「再生・調整」の「左右の確認」を開き、片側だけを再生します。実際に鳴る位置を確認して、「音声Lが物理左」または「音声Rが物理左」を選択してください。割当変更後も、左カードの設定は物理左、右カードの設定は物理右に対応します。向きや出力機器を変えた場合は再確認します。

上段でタブを切り替え、中央の設定欄をスクロールします。下段の停止ボタンは固定です。数値を押すと直接入力でき、入力ダイアログにも停止ボタンがあります。出力先は再生中にAudioTrackが報告するルートを表示します。停止中は前回のルートであることを明記します。

## 正弦波と広帯域音源

正弦波の初期値は1143 Hzです。プリセットまたは数値入力で周波数を選び、「右の位相 − 左の位相」を調整します。発振器の設定と、FIR・遅延・極性を含む処理全体の位相差を区別して表示します。ミュートや深い零点では位相差の数値を表示しません。

広帯域音源では同じサンプル列を左右へ渡します。「左右の時間差」は右の追加遅延から左の追加遅延を引いた値です。正なら右、負なら左が遅れます。通常のスライダーは±1000 µs、詳細調整の数値入力は±10000 µsです。1 µs単位の入力は補間による近似です。

ノイズの帯域制限は初期値300 Hz〜8 kHzです。スイープでは開始・終了周波数、時間、線形・対数、反復を指定します。「この側だけ／解除」は元のミュート状態を保存し、再度押すと復元します。反対側のボタンを押すと片側再生の対象を切り替えます。

WAVはPCM16/24/32、IEEE float32、モノラル・ステレオに対応します。ステレオではL採用、R採用、平均を選べます。平均では逆相成分が相殺される場合があります。読み込み後は停止状態で、シーク・ループ・ループ端のクロスフェードを操作できます。

WAVは8〜192 kHz、1 GiB以下、2時間以下に制限しています。異なるレートは読み込み時に48 kHzへ変換し、アプリのキャッシュへ保存します。長いファイルほど変換時間と空き容量が必要です。再生中の先読み量は固定です。参照権限を失った場合はWAVを選び直してください。

## FIRを画面で編集する

「FIR編集」で左・右を選び、フラット、グラフィックEQ、LPF、HPF、BPF、係数から設計方式を選択します。EQの橙色の点を上下へドラッグするか、周波数ポイントを選んでゲインを数値入力します。LPF・HPF・BPFは遮断周波数を入力します。FIR長は停止中に257・513・1025から選び、初期値は513です。

破線は目標、緑線は編集FIRの実現特性、青線は適用済みFIRです。振幅・位相・群遅延・インパルス応答を切り替えて確認します。短いFIRでは低域や急な変化を目標どおりに再現できない場合があります。

自動反映は初期値ONです。最後の編集から200 ms待って設計し、音声は約30 msで切り替えます。OFFにした場合は「反映」を押すまで音を変更しません。「変更取消」で適用済みの設定に戻ります。設定切替中は定常状態の測定には使用しないでください。

「左右同時編集」は以後の編集を両側に反映します。有効化だけで既存の左右設定を揃えることはありません。「左を両側へ」「右を両側へ」でFIRと有効状態をコピーします。

係数モードではタップ別の数値入力、複数値の貼り付け、CSV・JSON読込を利用できます。任意係数を正規化・中央移動する処理はありません。例えば`[1]`は遅延0のインパルスで、513タップの中央フラットとは256サンプル分の遅延差があります。バイパスは中央フラットと同じ遅延です。

## 保存と比較

最後の音響設定は自動保存します。再生状態は復元しません。「設定保存」「設定読込」でセッションJSONを入出力し、「FIR保存」でFIR単体JSONを保存します。CSVは係数1列で、先頭に任意の`coefficient`ヘッダーを付けられます。CSVにはレート情報がないため、取込時に設計レートを確認します。

A/Bは左右のゲイン・極性・ミュート・遅延・位相・FIRを保存します。切り替えても音源位置、共通出力ゲイン、左右割当は変更しません。FIR長を変更するとA/Bを消去します。

## レベルと理論グラフ

正弦波とスイープのピークは1です。ホワイトノイズの帯域制限前RMSは0.2、ピンクノイズも約0.2を目安とする固定係数で生成します。帯域制限後のRMSは帯域によって変わります。WAVは元のPCM値を保持し、自動音量正規化を行いません。float WAVには絶対値1を超える値があり得ます。

出力メーターは最終飽和処理の直前のデジタルピークを`20 log10(|x|)`で表示し、絶対値1を0 dBFSとします。表示下限は−120 dBFSです。絶対値1を超えた各chのサンプルをクリップ回数として数え、AudioTrackへ渡す前に±1へ飽和させます。独立AGC・リミッタはありません。

理論プレビューは選択した1周波数のパターンです。正面0°、物理右側が正角です。0 dBゲインの2音源が同相加算した振幅2を固定参照とし、共通出力ゲインを除きます。最大値への再正規化は行いません。

## Gitで管理するファイル

`.gitignore`で、ビルド成果物、キャッシュ、IDE設定、`local.properties`、署名鍵、ローカルの秘密情報ファイルを除外しています。認証情報を共有するビルド設定やソースコードに直接書き込まないでください。

`.gitattributes`で改行コードを指定しています。`gradlew`などのシェルスクリプトはLF、Windows用のバッチファイルはCRLFを使用します。

Gradle WrapperはJARを含めて管理し、`gradlew`にはGit上の実行権限を設定しています。日本語文書の編集規約は`AGENTS.md`にあります。
